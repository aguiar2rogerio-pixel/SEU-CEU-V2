# Entregáveis do MVP Seu Céu

- [ ] **PWA instalável e navegável:** O aplicativo deve ser criado do zero com layout prioritariamente móvel, nome Seu Céu, navegação simples entre Hoje, Meu mapa, Semana e Perfil, manifesto e ícones próprios, e recursos estáticos necessários para abrir após instalação.
- [ ] **Cadastro e transparência sobre dados natais:** O usuário deve poder cadastrar/editar nome, data de nascimento, horário exato, aproximado ou desconhecido, local opcional e fuso horário do nascimento; se o horário for desconhecido, o app pode usar 12:00 apenas como referência explicitamente aproximada, deve avisar que resultados dependentes do horário podem variar, não deve inventar horário exato e não deve apresentar Ascendente ou casas como calculados; o local pode ficar em branco e deve ser descrito como não usado no cálculo nesta versão, que não calcula casas nem Ascendente.
- [ ] **Cálculo e leitura semanal individual:** O app deve calcular localmente, sem API paga ou IA nesta primeira versão, as posições geocêntricas tropicais do Sol, Lua e planetas, os trânsitos de segunda-feira a domingo e aspectos relevantes (incluindo conjunções, retrógrados e ângulos usados pela aplicação), cruzando-os no aparelho com as posições natais salvas; a leitura deve ser montada por regras transparentes em português, diferir conforme o mapa, explicar aspectos calculados sem inventar posições, e identificar horário desconhecido/aproximado e limitações de precisão.
- [ ] **Painel, atualização e modo offline:** A tela principal deve priorizar o destaque e os conselhos da semana, exibir o intervalo de segunda a domingo e a data de cálculo; depois do primeiro carregamento/cálculo, a tela, perfil, mapa e leitura já gerada devem abrir offline e usar a última semana salva, indicando quando os dados foram atualizados; os cálculos implementados localmente não devem exigir conexão com serviço externo para regenerar a semana.
- [ ] **Armazenamento, privacidade e backup local:** O perfil e leituras devem ser salvos exclusivamente no aparelho, sem conta, banco de perfis ou envio de dados natais a API na primeira versão; a interface deve explicar que limpar dados do navegador ou trocar de aparelho pode apagar os dados, oferecer exportação e importação de backup JSON validado e permitir apagar dados locais com confirmação.
- [ ] **Histórico e manutenção simples:** O código deve estar organizado em módulos com nomes claros e comentários em português; o repositório GitHub público deve usar apenas a branch `main` e publicar no GitHub Pages pelo GitHub Actions; o README em português deve orientar, em passos simples, como executar, alterar textos de leitura, salvar mudanças, atualizar a publicação e fazer/restaurar backup; a validação funcional final deve ocorrer diretamente no endereço público do GitHub Pages.
