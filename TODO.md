# Entregáveis do MVP Seu Céu

- [ ] **PWA instalável e navegável:** O aplicativo deve ter layout prioritariamente móvel, nome Seu Céu, navegação simples entre Hoje, Meu mapa, Semana e Perfil, manifesto e ícones próprios, e recursos estáticos necessários para abrir após instalação.
- [ ] **Cadastro claro e confiável:** O usuário deve poder cadastrar/editar nome, data de nascimento, horário exato, aproximado ou desconhecido, local e fuso horário do nascimento. Para um cadastro novo, nenhuma precisão nem horário deve vir presumido: a pessoa escolhe explicitamente entre exato, aproximado ou “não sei”; se informar um horário, deve preencher hora e minutos. Antes de enviar, a tela deve explicar que o horário influencia a Lua e o Ascendente; se a pessoa não souber, pode continuar e o app deve deixar sem confirmação os resultados que dependem desse dado, sem inventar precisão. A tela deve comunicar que o cálculo acontece no aparelho e que dados natais não são enviados para uma IA.
- [ ] **Página pós-cadastro com os três pilares:** Depois do cadastro e do cálculo, a primeira página deve destacar Sol, Lua e Ascendente no topo e exibir abaixo as interpretações correspondentes, sem exigir a abertura de um modal ou de um botão chamado “leitura aprofundada”. Quando faltar horário ou outro dado necessário, a tela deve explicar com clareza o que não pôde ser confirmado. Antes do acesso, a página pode apresentar brevemente as áreas existentes Hoje, Meu mapa e Semana, sem duplicar seu conteúdo nem prometer recursos inexistentes. O núcleo de cálculo existente deve permanecer inalterado.
- [ ] **Transição simulada de acesso gratuito:** A página dos pilares deve apresentar o acesso gratuito de teste e um botão ativo para liberar o restante do aplicativo. Ao tocar, o usuário deve acessar as áreas Hoje, Meu mapa, Semana e Perfil, sem checkout, cobrança ou confirmação de compra. A liberação deve ficar isolada como modo de teste, preparada para futura substituição por um fluxo de checkout com validação real de pagamento.
- [ ] **Cálculo e leitura semanal individual:** O app deve calcular localmente, sem API paga ou IA nesta primeira versão, as posições geocêntricas tropicais do Sol, Lua e planetas, os trânsitos de segunda-feira a domingo e aspectos relevantes (incluindo conjunções, retrógrados e ângulos usados pela aplicação), cruzando-os no aparelho com as posições natais salvas; a leitura deve ser montada por regras transparentes em português, diferir conforme o mapa, explicar aspectos calculados sem inventar posições, e identificar horário desconhecido/aproximado e limitações de precisão.
- [ ] **Áreas restantes, atualização e modo offline:** Depois de liberar o acesso de teste, as telas Hoje, Meu mapa, Semana e Perfil devem continuar acessíveis com suas funções existentes; o conteúdo semanal não deve ser duplicado na página dos pilares. Depois do primeiro carregamento/cálculo, a tela, perfil, mapa e leitura já gerada devem abrir offline e usar a última semana salva, indicando quando os dados foram atualizados.
- [ ] **Armazenamento, privacidade e backup local:** O perfil e leituras devem ser salvos exclusivamente no aparelho, sem conta, banco de perfis ou envio de dados natais a uma API na primeira versão; a interface deve explicar que limpar dados do navegador ou trocar de aparelho pode apagar os dados, oferecer exportação e importação de backup JSON validado e permitir apagar dados locais com confirmação.
- [ ] **Histórico e manutenção simples:** O código deve estar organizado em módulos com nomes claros e comentários em português; o repositório GitHub público deve usar apenas a branch `main` e publicar no GitHub Pages pelo GitHub Actions; o README em português deve orientar, em passos simples, como executar, alterar textos de leitura, salvar mudanças, atualizar a publicação e fazer/restaurar backup; a validação funcional final deve ocorrer diretamente no endereço público do GitHub Pages.
